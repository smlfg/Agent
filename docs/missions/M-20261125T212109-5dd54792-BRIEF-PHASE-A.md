## Bausteine
1. `scripts/chunks/collect.mjs` → `scripts/chunks/.out/sources/<id>.json`
   `{id, source_kind, url, title, text, meta, source_hash}`; `text` auf ≤ 8000 Zeichen gekürzt,
   `source_hash = sha256(text)`.
   - github: `gh repo list smlfg --visibility public --limit 300 --json name,isFork,description,repositoryTopics,homepageUrl,url,pushedAt`,
     Forks raus; README per `gh api repos/smlfg/<name>/readme -H "Accept: application/vnd.github.raw"`
     (fehlt → nur Metadaten). id `gh-<name>` (klein, [a-z0-9-]).
   - web: `content/sources.json` (lege an) mit `sites[]` = agentfähig.de (xn--agentfhig-02a.de),
     human-agent-interface.com, humanagentinterface.de, humanagentcontrol.com, samuelfleig.com,
     agent-human-interface.com (Samuel ergänzt bis 9). Je Site: Startseite + Unterseiten aus
     `sitemap.xml`, sonst gleiche-Host-Links der Startseite; global max. 15 Unterseiten.
     HTML→Text mit Built-ins (script/style/nav/footer/header entfernen, Tags strippen, Entities,
     Whitespace) — kleine Glue-Funktion, keine Lib. Nicht erreichbare Seiten loggen, weiter.
     id `web-<host>-<slug>`.
   - manual: `scripts/chunks/.out/manual/*.md` (Notion-/Plaud-Exporte, legt der Orchestrator ab)
     1:1 übernehmen, `source_kind` aus Frontmatter `kind: notion|plaud|manual`.
   - CLI: `node scripts/chunks/collect.mjs [--only github|web|manual]`.
2. `scripts/chunks/condense.mjs` — baut Batches (Standard 8 Quellen) aus Quellen, deren
   `source_hash` nicht in `.out/cache.json` steht; ruft pro Batch
   `codex exec --ephemeral --skip-git-repo-check -s read-only -m gpt-5.6-luna --output-schema scripts/chunks/batch.schema.json -o <datei> -C <leerer tmp-ordner> <prompt>`
   (Prompt per stdin oder Argument), max. 3 parallel, Retry 1×. Prompt-Vorlage
   `scripts/chunks/prompt.md` (~300 Tokens): je Quelle genau ein Chunk, Quellen strikt
   getrennt (`<<<SOURCE id=…>>> … <<<END>>>`), nichts aus anderen Quellen übernehmen,
   Deutsch, dritte Person, ≤ 120 Wörter, sachlich, keine Superlative, keine Namen Dritter,
   keine Kontaktdaten, `link` nur wenn wörtlich in der Quelle (Repo-URL/Homepage), sonst null,
   `aliases` = Namen/Begriffe, unter denen man danach fragen würde, `waypoints` aus
   `["what-this-is","creator","product-for-x","*"]`.
   Schreibt `.out/chunks/<id>.json`, aktualisiert Cache, loggt `usage` (aus `--json`) nach
   `.out/usage.jsonl`. Flags: `--batch N`, `--limit N`, `--dry-run` (zeigt Batches, kein Aufruf).
3. `scripts/chunks/batch.schema.json` — `{chunks:[{id,title,text,topics[],aliases[],waypoints[],link}]}`.
4. `scripts/chunks/check.mjs` — prüft je `.out/chunks/*.json`: Schema, ≤ 120 Wörter, id kommt
   aus der Quelle, `link` ∈ Quelltext, Dubletten; Hinweise (E-Mail, Telefon, Personennamen-
   Heuristik) in `hints[]` — Hinweise blockieren nicht. Schreibt
   `src/agent/knowledge/<id>.md` mit Frontmatter
   `id,title,waypoints,topics,aliases,link,source,source_kind,source_hash,updated_at,visibility: public`
   — **niemals** `approved_hash`. Bestehendes `approved_hash` in einer vorhandenen Datei bleibt
   nur erhalten, wenn sich der Inhalt nicht ändert.
5. `scripts/chunks/skim.mjs` → `scripts/chunks/.out/skim.html` (eine Datei, inline CSS/JS,
   läuft per file://): Gruppen in dieser Reihenfolge: „Veröffentlichungsfreigabe"
   (source_kind notion|plaud|manual und alles mit topic `person`), dann web, dann github.
   Je Chunk: Titel, Text, Quelle, Link, Hinweise, Checkbox (Standard an, bei Hinweisen aus).
   Button „Freigaben exportieren" → lädt `approvals.json` (`{approved:[id…]}`) herunter.
6. `scripts/chunks/approve.mjs --from <approvals.json>` — setzt für die genannten Chunks
   `approved_hash: sha256(<Datei ohne approved_hash-Zeile>)`, entfernt ihn bei allen anderen.
   Export `chunkHash(text)` für Phase B.
7. `scripts/chunks/migrate-knowledge.mjs` — erzeugt ohne LLM aus `src/agent/knowledge.json`
   (owner, offerings, approach, faq, projects_public) Chunks `kj-<abschnitt>-<id>.md`,
   `source_kind: manual`, `source: knowledge.json:<pfad>`. knowledge.json bleibt unverändert.
8. `tests/chunks.test.js` (node:test, offline, Fixtures unter `tests/fixtures/chunks/` — dieser
   Pfad ist ebenfalls erlaubt): HTML→Text, Batch-Bildung + Cache, check (Link-Prüfung,
   Wortgrenze, Hinweise), Hash-Freigabe (Änderung invalidiert), Migration.
