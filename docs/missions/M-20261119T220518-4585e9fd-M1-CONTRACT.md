# M1 Living Surface — Komponenten- und State-Vertrag

Mission `M-20261119T220518-4585e9fd`. Integrator: Claude Code. Stack: plain ES modules + CSS, kein Framework, kein Build. Dev: `npm run dev` → http://127.0.0.1:5173. Tests: `npm test` (`node --test`).

## Owner-Vorgaben (19.11.2026)
Englisch · Text zuerst, keine Voice · Besucher spricht zuerst, Agent ohne Eingabe still · nur aktuelles Paar (Eingabe + Antwort), Älteres löst sich nach oben auf · kein Verlauf, kein Regler · Unterbrechen erlaubt · flüssig/natürlich vor sofort · Reload = Neustart (keine Persistenz).

## Fixe Dateien (Integrator, nicht ändern)
`src/living-surface.html`, `src/main.js`, `src/state/store.js`, `src/dev/devAgent.js`, `src/styles/base.css`, `src/vendor/openvoiceui/**` (MIT, unverändert).

## State (`src/state/store.js`)
`state = { phase, prompt, answer, turn, dev }`, `phase ∈ dormant | idle | listening | thinking | speaking`.
Events: `AWAKE` · `INPUT {value}` · `SUBMIT {prompt}` (unterbricht thinking/speaking, turn+1) · `RESPONSE_START {turn, dev}` · `RESPONSE_PROGRESS {turn, text}` · `RESPONSE_END {turn, text}` · `RESPONSE_ERROR {turn}`. Events mit veraltetem `turn` werden ignoriert.
`createStore()` → `{getState, dispatch, subscribe(fn(state, prev, event)) → unsubscribe}`.
`main.js` setzt `#stage[data-phase]` und dispatcht `AWAKE` nach 5000 ms.

## Dev-Agent (`src/dev/devAgent.js`)
`pickResponse(prompt) → string` deterministisch. `respond(prompt, {signal, delayMs=700}) → Promise<{text, dev:true}>`, Abort → `AbortError`.

## A — Presence
Besitzt: `src/presence/presence.js`, `src/styles/presence.css`.
`export function mountPresence({ root, store, reducedMotion }) → { pause(), resume(), destroy() }`.
- Nutzt `EyeFace` aus `../vendor/openvoiceui/face/EyeFace.js` (standalone: `new EyeFace().init(faceBox)`), Vendor-Dateien nicht ändern.
- Phase → Mood: dormant = Augen geschlossen (eigene Klasse, Lider unten, gedimmt), idle → neutral, listening → listening, thinking → thinking, speaking → happy.
- Erwachen dormant → idle: sanftes Öffnen der Lider über ca. 1.2 s.
- `#motion-toggle`: pausiert/reaktiviert Blinzeln, Umsehen, Pupillen-Animation; `aria-pressed` + Label „Pause motion“/„Resume motion“.
- reducedMotion: keine Zufallsbewegung, keine Mausverfolgung, kein Lid-Übergang; Augen statisch offen ab idle.

## B — Conversation
Besitzt: `src/conversation/conversation.js`, `src/conversation/typewriter.js`, `src/styles/conversation.css`.
`export function mountConversation({ root, store, agent, reducedMotion }) → { destroy() }`.
`export function createTypewriter({ text, wordDelayMs = 45, reducedMotion = false, schedule = setTimeout, cancel = clearTimeout, onUpdate, onDone }) → { start(), stop() }`
- Typewriter wortweise (Leerzeichen bleiben erhalten), `onUpdate(sichtbarerText)` pro Wort, `onDone()` am Ende; reducedMotion: `start()` ruft synchron `onUpdate(volltext)` und `onDone()`; `stop()` bricht ohne `onDone` ab.
- Composer `#composer-input`: Tippen → `INPUT`; Enter/Senden → `SUBMIT`, Feld leeren, Fokus bleibt; nie gesperrt.
- Pro Turn: `agent.respond(prompt, {signal})` mit AbortController; neue Eingabe bricht alten Turn ab.
- `#pair` zeigt nur das aktuelle Paar: Eingabe-Echo (gedämpft) + Antwort. Beim neuen SUBMIT steigt das alte Paar nach oben weg und löst sich auf (CSS, ~600 ms; reducedMotion: sofort weg).
- Fertige Antwort einmal in `#live` (aria-live) schreiben.
- Kein innerer Scrollbereich, gut lesbar (max ~38rem Zeilenlänge), Mobile: Composer unten sichtbar.
